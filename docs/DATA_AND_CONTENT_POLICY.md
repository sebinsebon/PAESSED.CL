# Data and Content Policy

Esta politica existe para evitar errores legales, de privacidad y de calidad
educativa antes de que el proyecto crezca.

## Regla Principal

Solo se debe agregar contenido al repositorio cuando exista permiso claro para
usarlo y redistribuirlo en un proyecto open source.

## Permitido

- Documentacion propia del proyecto.
- Ejemplos sinteticos creados para explicar estructuras.
- Schemas, contratos y fixtures pequenos sin datos reales.
- Taxonomias curriculares redactadas por el equipo y basadas en fuentes citables.
- Referencias o enlaces a fuentes externas, cuando corresponda.

## No Permitido

- PDFs privados de ensayos.
- Preguntas de terceros copiadas sin permiso.
- Bancos completos de contenido protegido.
- Respuestas reales de estudiantes.
- Datos personales o identificables.
- Imagenes, graficos o assets externos sin licencia compatible.

## Preguntas PAES y DEMRE

El proyecto puede documentar como se usaria contenido oficial o autorizado, pero
antes de incluir preguntas, imagenes o explicaciones derivadas se debe revisar:

- Fuente exacta.
- Permiso de uso.
- Permiso de redistribucion.
- Licencia aplicable.
- Forma correcta de atribucion.

Si no hay claridad, no se agrega al repositorio.

## Ensayos Privados

Los ensayos externos o privados deben tratarse con enfoque local-first.

El repositorio puede contener:

- El contrato `exam.json`.
- Ejemplos sinteticos.
- Herramientas de procesamiento.

El repositorio no debe contener:

- PDFs privados originales.
- Salidas generadas desde material privado real.
- Imagenes extraidas de ensayos privados.

## Datos de Estudiantes

Los ejemplos de usuario deben ser ficticios. No uses nombres, correos, puntajes,
historiales ni respuestas reales.

## Antes de Subir Contenido

Revisa esta lista:

- El contenido fue creado por el proyecto o tiene licencia compatible.
- No contiene datos personales.
- No contiene material privado.
- La fuente y licencia estan documentadas.
- El archivo es necesario para avanzar el proyecto.
